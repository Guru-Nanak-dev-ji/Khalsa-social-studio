# KIDO ONE — Shared Memory Architecture v0.1 (Step 09)

Status: **PROPOSED / NON-DEPLOYING**. Owner: DK 01. Related: #158, draft PR #159, founder decision DEC-003. This document does not amend historical rules or authorize outbound publication.

## Source of truth and access
- **Canonical event store (future):** managed PostgreSQL with append-only `events` table; unique `event_id`, unique `idempotency_key`, `seq` generated by database transaction; tenant/project isolation; immutable payload, `previous_hash`, `event_hash`, source URI and approval evidence.
- **Read model:** derived projections for COMMANDS, DECISIONS, CONFLICTS, TASKS, AI_REVIEWS, EVIDENCE and ARCHIVE. Rebuildable from events; projection updates never rewrite history.
- **GitHub:** versioned public code/specs and sanitized Issues; **never** private commands, personal data, credentials or access tokens.
- **Google Drive:** human-readable reports, source links and audit summaries; Drive comments are not the transactional event store.
- **Other AI platforms:** explicit connector/API or human copy-paste handoff. No assumption that naming a bot in an issue connects it.

## Authority model
- Founder DK 01: constitutional/policy ratification and explicit release gates.
- Human editors: scoped review and publishing approval only within assigned roles.
- AI workers: draft/research/check/test; may request execution through policy gateway, not grant themselves new permissions.
- Auditor: read-only event evidence and independent verification.
- All roles: least privilege; identity of human vs AI always recorded.

## Safe write protocol
1. Authenticate caller and verify role and project scope.
2. Verify request schema, immutable source pointer and unique idempotency key.
3. Read current policy version and historical commands in one transaction.
4. Detect duplicate, conflicting or superseding instructions; on conflict append `CONFLICT_RAISED` and stop execution pending founder decision.
5. Append event with server timestamp and hash chain under serialized transaction/row lock. Never use the single-process JSONL prototype for concurrent writers.
6. Return event ID and read-after-write verification. Export signed or independently anchored checkpoints and encrypted backups on schedule.
7. Process external actions through separate outbox worker with explicit scoped approval; default deny, retries with idempotency, rate limits, receipts and emergency pause.

## Proposed event kinds
`COMMAND_RECEIVED`, `DECISION_RECORDED`, `CONFLICT_RAISED`, `CONFLICT_RESOLVED`, `TASK_CREATED`, `TASK_ASSIGNED`, `TASK_RESULT_RECORDED`, `EVIDENCE_ATTACHED`, `PUBLISH_SCOPE_APPROVED`, `PUBLISH_REQUESTED`, `PUBLISH_POLICY_DENIED`, `PUBLISH_EXECUTED_VERIFIED`, `AUTOMATION_PAUSED`.
